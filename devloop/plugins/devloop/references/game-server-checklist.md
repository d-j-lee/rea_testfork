# 게임 서버 컨텐츠 리스크 체크리스트

설계검토의 관점 목록, 검증 설계의 시드, 이슈 조사의 가설 후보로 함께 쓴다. 해당 없는 분류는 "해당 없음(이유)"으로 지나가고, 팀 경험은 `.devloop/knowledge/checklist.md`에 추가한다(이 파일은 플러그인 기본값).

## 1. 상태와 수명주기
- 엔티티(미션·퀘스트·매치·파티·우편)의 상태 전이를 표로 그릴 수 있는가? 금지 전이(수령 후 진행, 만료 후 수령)는?
- 접속 끊김·재접속·서버 이동(채널/로비↔게임) 중간에 상태가 어떻게 되는가? 매치 중 이탈·강제 종료·호스트 이전은?
- 진행 중 데이터 테이블/설정이 바뀌면(핫픽스) 이미 진행 중인 인스턴스는 어느 버전을 따르는가?

## 2. 동시성·멱등성 (중복 지급의 주범)
- 같은 요청이 두 번 오면? 클라이언트 재시도, 네트워크 재전송, 서버 간 재시도, 큐 재처리, 다중 세션(같은 계정 두 클라이언트).
- "확인 후 갱신"이 원자적인가(조건부 UPDATE, 유니크 제약, 트랜잭션 격리수준, 분산 락)? 외부 호출이 그 사이에 끼는가?
- 멱등 키(요청 ID)가 있고 응답 재생이 가능한가? 타임아웃 시 클라이언트가 무엇을 하는가?
- 캐시(Redis)와 DB의 쓰기 순서, 실패 시 보상(롤백) 경로는?

## 3. 시간·리셋·지역
- 리셋 기준이 UTC인가 지역별인가? 서버 로컬 시간대·DST(유럽/북미)·윤초·클라이언트 시계 신뢰 여부.
- 경계값: 23:59:59.999 / 00:00:00 / 리셋 직전 시작해 직후 끝난 매치는 어느 주기로 집계?
- 이벤트 기간 표기(11/1~11/7)의 시간대와 포함/배제 경계. 서버 간 시계 편차.

## 4. 경제·보상·악용
- 보상 원천과 상한(일/주/계정), 오버플로(정수 범위), 음수 수량, 소수점 반올림.
- 재화 순환(획득→소모) 밸런스가 깨지는 조합: 이벤트 2배 × 중복 수령 × 환불.
- 악용 경로: 패킷 변조·리플레이, 봇/매크로, 승패 조작(짜고 치기), 다계정, 환불(스팀) 후 재화 유지.
- 우편/인벤토리 가득 참·만료·롤백 시 보상 유실 또는 복제.

## 5. 데이터 테이블(기획 데이터)
- 참조 무결성: 존재하지 않는 아이템·보상 ID, 중복 키, 빈 값, 0/음수 목표치, 타입 불일치.
- 테이블 간 일관성(미션 표 ↔ 아이템 표 ↔ 로컬라이즈 문자열), 노출 조건(레벨·지역·플랫폼).
- 배포 단위: 테이블만 바뀌는 핫픽스가 서버 코드 가정(개수·순서·범위)을 깨지 않는가?

## 6. 호환성·배포
- 롤링 배포 중 구/신 클라이언트·서버 공존: 프로토콜 필드 추가/삭제, 기본값, 버전 협상.
- DB 스키마 변경: 대형 테이블 잠금, 백필, 역방향 호환, 롤백 가능성.
- 기능 플래그·킬 스위치, 단계적 오픈, 롤백 절차와 데이터 정합성.

## 7. 성능·용량
- 핫패스(틱·매치 종료·로그인 폭주) 추가 비용, N+1 쿼리, 인덱스 누락, 전체 스캔.
- 리셋 순간·이벤트 시작 순간의 동시 요청 폭주(thundering herd), 재시도 폭풍.
- 외부 의존(보상/결제/스팀 API) 지연·장애 시 타임아웃·서킷브레이커·큐 적체.

## 8. 관측·운영
- CS가 "누가 언제 무엇을 받았나"를 답할 수 있는 로그/DB 기록이 있는가(요청 ID, 사유, 서버, 빌드)?
- 이상 탐지 지표(중복 지급, 실패율, 지연), 알람 기준.
- GM 도구로 조회·회수·보상이 가능한가? 대량 처리 시 감사 로그와 dry-run.

## 9. 보안·개인정보 (글로벌)
- 서버 권한(authority): 클라이언트가 보낸 값(진행도·결과)을 믿는가?
- 개인정보(SteamID, IP, HWID)의 로그·조회 범위, 보존 기간, 지역 규제(GDPR 등).

## 10. 기획 의도와 명세 공백
- 명세가 침묵하는 경우의 동작(실패·취소·중복·만료)을 기획이 정했는가? → 질문으로 남긴다(`case ask`).
- 수치·문구·노출 조건의 출처가 기획서/테이블/공지 중 어디인지, 서로 일치하는지.
