# 조사 플레이북 (버그·라이브 이슈)

## 첫 15분: 사실을 고정한다
1. **증상 정규화**: 무엇이(기대 vs 실제), 누가(계정·uid·지역·플랫폼), 언제(**UTC로 변환**, 원문 시각과 시간대 병기), 어디서(서버·채널·매치), 얼마나(1명/다수, 지속/간헐), 빌드(클라/서버).
   - 티켓의 현지 시각을 그대로 쓰지 않는다. 예: "오후 5시(CEST)" → 15:00Z (10월 말까지 CEST=UTC+2).
2. **변화 지점**: 증상 시작 무렵의 배포·데이터 테이블·설정/플래그·외부 서비스·운영 조치(GM, 수동 DB). `git log --since`, 배포 이력 테이블, 공지.
3. **로그 전체 모양**: `log scan`(템플릿) → `log diff`(전후 창, 먼저 `--level WARN`) → 특정 사용자/요청 `log timeline --key`.
4. **영향 범위 초안**: 읽기전용 집계 쿼리(`db query --save`, live는 결과 상한 필수).

## 가설 범주 (게임 서버에서 흔한 순)
| 범주 | 판별 증거(싼 것부터) |
| --- | --- |
| 멱등성·재시도·경합 | 같은 키 이중 처리 타임라인(Δms), 요청 ID 상이, 재시도 플래그, 동시 봇 재현 |
| 데이터 테이블 오류 | 테이블 diff, 참조 무결성, 영향이 특정 ID에 집중 |
| 시간·리셋·시간대 | 이벤트 시각이 특정 UTC/KST 경계에 몰림, 지역별 편차, 경계 봇 시나리오 |
| 설정·플래그·배포 | 시작 시각=배포 시각, 서버별 빌드 차이, 롤링 중 구/신 혼재 |
| 버전 스큐(클라/서버) | 클라 버전별 분포, 프로토콜 필드 누락 로그 |
| 캐시·DB 불일치 | 캐시와 DB 값 대조, 무효화 로그, 장애 이력 |
| 외부 의존(보상·결제·스팀) | 지연·오류 템플릿 증가, 타임아웃 후 재시도 연쇄 |
| DB(교착·타임아웃·격리) | slow/deadlock 로그, 부분 커밋 흔적 |
| 운영 조치 | GM 로그, 수동 쿼리 이력 |
| 악용·치트 | 비정상 빈도·패턴, 특정 계정군 집중 |

각 가설에 **지지·반박 근거와 판별 방법**을 적고, 결론을 가장 크게 가르는 가장 싼 확인부터 한다. 가설 하나에 몰입하지 않는다: 반박 근거를 찾는 단계를 넣는다.

## 재현
- 재현 없이는 원인이 추론이다(evidence.md). 재현 수단: 단위/통합 테스트(`ev run`), 봇 시나리오(`bot run --save`), 로컬 서버 + GM 명령.
- 경합은 확률적이다: `repeat`로 반복하고 분포(예: 10회 중 7회 중복)를 기록한다. 한 번 통과는 "경합 없음"의 증거가 아니다.
- 재현 환경과 실서버의 차이(격리수준, 지연, 데이터 규모)는 미확인으로 남긴다.

## 대응 계획
- 코드 수정(fix 스킬), 설정/플래그, **데이터 보정은 사람이 실행**(스크립트 + dry-run 집계 + 백업/롤백 + 멱등), 보상 정책은 기획·운영 결정(`case ask`/`case decide`), 공지·CS 답변(report 스킬).
- 되돌리기 어려운 항목은 실행 전 합의 기록을 남긴다.

## 흔한 함정
- 서버 로그 시각(KST 등)과 DB 시각(UTC)·티켓 시각(현지)을 섞어 비교.
- 여러 서버 로그를 시각만으로 정렬해 인과를 단정(시계 편차).
- 템플릿 상위만 보고 저빈도 ERROR를 놓침 → `--level WARN`으로 다시 본다.
- 잘린 쿼리/로그 결과(returned < matched)를 전체로 오인.
- "재현 안 됨"을 "문제 없음"으로 결론.
