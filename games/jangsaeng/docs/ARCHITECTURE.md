# 장생 아키텍처

한 벌의 시뮬레이션 코어가 Node 서버(온라인)와 브라우저(오프라인)에서 똑같이 돈다. 클라이언트는 언제나 같은 프로토콜로 호스트와 대화하고, 그 호스트가 원격인지(WebSocket) 같은 페이지 안인지(루프백)는 모른다.

```
┌──────────────── client (DOM) ────────────────┐      ┌──────── server (Node) ────────┐
│ ui/      제목·HUD·선택지·세월·메뉴·엔딩 (DOM)   │      │ main.ts  http 정적 + /ws       │
│ game/    프레임 루프·보간·카메라·장면 합성       │      │ store.ts JSON 프로필(원자적 저장) │
│ render/  지형·건물·캐릭터·이펙트 (Canvas2D)     │      └──────────────┬────────────────┘
│ audio/   절차적 국악 음악·효과음 (WebAudio)     │                     │
│ net/     WebSocket ─┐  루프백 ─┐ (offline.ts)   │                     │
└─────────────────────┼─────────┼────────────────┘                     │
                      │         │  protocol.ts (ClientMsg / ServerMsg)  │
┌─────────────────────▼─────────▼──────── shared (순수, DOM·Node 없음) ──▼──────────┐
│ host/    GameHost · Session(개인 서사) · Channel(시대 채널) · Bot(◇ 동료) · parse  │
│ sim/     World: 이동·충돌·전투·적 AI·전투 이벤트·스냅샷 (타일·초 단위, 결정론)      │
│ rules/   PlayerSave 위의 순수 함수: 성장·효과 대수·정치·수명·의심·세월·엔딩         │
│ content/ 데이터: 16개 챕터·적·기술·아이템·출신·품계·동료·엔딩 (schema.ts가 계약)    │
│ map/     위경도 기반 한반도 생성기 (시드 결정론, 시대별 구조물·충돌)               │
└───────────────────────────────────────────────────────────────────────────────┘
```

## 계층과 의존 방향

의존은 안쪽으로만 흐른다: `content/map` → `rules`/`sim` → `host` → `server`/`client`.

- `tsconfig.shared.json`은 `lib: ES2023`, `types: []`로 `src/shared`를 검사한다. 공용 코드가 DOM이나 Node API를 쓰면 컴파일이 실패한다.
- `tsconfig.client.json`(DOM)과 `tsconfig.server.json`(Node, 테스트 포함)이 각각 바깥 계층을 검사한다.
- TypeScript는 지울 수 있는 문법만 쓴다(`erasableSyntaxOnly`). 그래서 Node 22.18+가 빌드 없이 `.ts`를 바로 실행한다(서버, 테스트).

## 시간 모델: 개인의 시간, 시대의 공간

- **개인 시간**: 연도·챕터·단계는 `PlayerSave`에만 있다. 이야기 목표를 끝내거나 세월을 보낼 때만 앞으로 간다. 접속하지 않은 시간은 수명을 쓰지 않는다.
- **시대 채널**: 같은 챕터에 있는 사람끼리 `Channel` 하나(정원 40, 넘치면 새 샤드)를 공유한다. 채널마다 `World`가 하나다.
- **NPC와 스폰 창**: 채널 안에서 가장 앞선 사람의 단계를 따른다(`Channel.updateStep`). 목표 표식(!)은 사람마다 따로 계산한다(`npcMarker`).
- **공동 실록**: 채널의 협동 게이지다. 완성하면 참여자의 `zeitgeist` 플래그가 오르고, 엔딩 점수에 최대 +5까지 더해진다.

## 권위와 신뢰 경계

- 클라이언트 메시지는 `unknown`으로 들어온다. `host/parse.ts`가 모양·범위·길이를 검사한 뒤에야 쓴다. 이름·채팅은 정규화하고 길이를 제한한다.
- 입력은 의도(이동 벡터·버튼)만 담는다. 위치·피해·보상은 호스트가 정한다.
- 선택지는 현재 열린 프롬프트 id와 활성 옵션만 받는다. 조건은 서버에서 다시 평가한다.
- 숙청·판정 굴림은 `hashRoll(save.seed, 사건id)`다. 같은 사건은 다시 불러와도 결과가 같다(세이브 스커밍 방지).
- 서버 측 제한: WebSocket 메시지는 8KB, 초당 40개다. 정적 파일 경로 탈출을 막고, 프로필 토큰 형식을 검사한다.

## 결정론

- 맵: `generateMap(seed)`. 서버·오프라인 호스트·클라이언트가 각자 같은 타일을 만들기 때문에 맵은 전송하지 않는다.
- 월드: 고정 스텝(50ms) + 시드 RNG를 쓴다. 공용 시뮬레이션은 `Math.random`/`Date`를 쓰지 않는다. 예외는 접속 토큰 생성(`crypto.getRandomValues`)뿐이다.

## 데이터 주도 콘텐츠

챕터는 `ChapterDef` 데이터다.

- **흐름**: `steps[]`(연도·내레이션·목표) → 목표 종류(`talk`/`reach`/`defeat`/`battle`/`prompt`/`collect`/`auto`) → 선택지(`PromptDef`) → 효과 대수(`Effect`)와 조건 대수(`Cond`).
- **효과 처리**: 순수 효과(능력치·국운·총애·수명·의심·분기 플래그 …)는 `rules.applyEffects`가 세이브에 적용한다. 런타임 효과(다음 프롬프트·전투 시작·이동·목표 완료)는 `EffectOutcome`으로 돌려주고, `Session`이 실행한다.
- **무결성 검사**: `tests/unit/content.test.ts`가 모든 참조(지명·스프라이트·적·선택지·전투·NPC·기술·아이템·파벌)와 금칙어를 검사한다. 새 챕터를 추가할 때 이 테스트가 1차 관문이다.

## 오프라인 모드(시연용 웹 빌드)

- `dist/jangsaeng.html` 한 파일에 모든 코드가 들어 있다. 페이지 안에서 `createGameHost({mode: "offline"})`가 돌고, 클라이언트는 루프백으로 붙는다.
- 프로필은 `localStorage`에 저장한다. 접근이 실패하면 메모리로 대체한다.
- 시뮬레이션 동료(◇)가 채널을 채운다. UI와 채팅에 시뮬레이션임을 항상 표시한다.

| `npm test` | 단위·통합: 맵, 물리, 규칙, 월드, 콘텐츠 무결성, 호스트 전체 아크(1361→1910 자동 진행) |
